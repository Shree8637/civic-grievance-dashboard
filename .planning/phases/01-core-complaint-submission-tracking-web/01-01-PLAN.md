<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → API | Untrusted citizen input crosses to backend validation |
| API → Database | Validated data written via parameterized queries |
| Browser → Supabase Storage | Direct upload (Plan 3) — separate trust boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Spoofing | POST /api/complaints | medium | mitigate | No auth on citizen endpoints (by design); rate limiting via reverse proxy in production |
| T-01-02 | Tampering | complaintCreateSchema validation | low | mitigate | Shared Zod schema enforces same rules client+server; backend re-validates all input |
| T-01-03 | Repudiation | Tracking ID generation | low | accept | Sequential IDs not cryptographic; audit trail via created_at + IP logging (future) |
| T-01-04 | Information Disclosure | GET /api/track/:trackingId (Plan 2) | medium | mitigate | Public endpoint by design; only returns status + description (no phone in response) |
| T-01-05 | Denial of Service | POST /api/complaints | medium | mitigate | Body size limit (express.json({limit:'1mb'})), rate limiting via nginx/Cloudflare in prod |
| T-01-06 | Elevation of Privilege | Database connection | low | mitigate | Least-privilege DB user; parameterized queries prevent SQL injection |
| T-01-SC | Tampering | npm packages (all) | high | mitigate | Package legitimacy audit completed in RESEARCH.md — all [OK]/[Approved] |
</threat_model>
