<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Citizen Browser → Frontend | Untrusted user input (description, location, phone, photo) enters React app |
| Frontend → Backend API | POST /api/complaints crosses trust boundary; backend must validate all input |
| Backend → PostgreSQL | Parameterized queries only; no string interpolation |
| Frontend → Supabase Storage | Direct upload with anon key; bucket policy restricts to authenticated/anon uploads only |
| Backend → Nominatim | External geocoding API; rate-limited, cached, no auth |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Spoofing | POST /api/complaints | medium | mitigate | Zod validation on all fields; phone normalization; source='web' enforced server-side |
| T-01-02 | Tampering | Complaint data in transit | low | mitigate | HTTPS in production; CORS restricted to known origins |
| T-01-03 | Repudiation | Tracking ID generation | low | accept | Sequential GD-XXXXX provides audit trail; not cryptographically signed |
| T-01-04 | Information Disclosure | GET /api/track/:trackingId | medium | mitigate | Tracking ID is not secret (given to citizen); endpoint returns only non-PII fields (no phone in response) |
| T-01-05 | Denial of Service | Nominatim rate limit (1 req/s) | high | mitigate | In-memory cache keyed by rounded coords (4 decimals) with 24h TTL; pre-geocode demo data |
| T-01-06 | Elevation of Privilege | Supabase Storage upload | low | mitigate | Anon key only allows upload to public bucket; no delete/modify; RLS not needed for public bucket |
| T-01-07 | Tampering | Photo upload path manipulation | low | mitigate | Path generated server-side pattern: complaints/{trackingId}/{timestamp}-{random}.{ext}; frontend uses same pattern |
| T-01-SC | Tampering | npm package installs | high | mitigate | Package Legitimacy Audit in RESEARCH.md shows all packages [OK]/[Approved]; no [SUS]/[SLOP] packages |
</threat_model>
