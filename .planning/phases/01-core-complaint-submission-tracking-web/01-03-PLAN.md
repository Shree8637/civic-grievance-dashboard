       - `loadWards()`: Reads file once, parses JSON, caches in module-level variable. Validates structure (FeatureCollection, features array).
       - `assignWard(latitude, longitude)`: Creates turf.point([lng, lat]) — NOTE: turf uses [lng, lat] order. Iterates features, calls turf.booleanPointInPolygon(point, feature.geometry). Returns feature.properties.id (matches wards.id in DB) on first match. Returns null if no match (outside Mumbai).
       - `getWardById(id)`: Returns ward feature for admin display (Phase 5)
       - Error handling: Try/catch on file read, log error, return empty cache

    3. **geocodingService.ts** (new):
       - In-memory cache: `Map<string, { wardId: number|null, displayName: string, expiry: number }>` keyed by `${lat.toFixed(4)},${lng.toFixed(4)}` (4 decimal places ≈ 11m precision)
       - `reverseGeocode(latitude, longitude)`: 
         - Check cache for key, if exists and not expired (Date.now() < expiry) → return cached
         - Call Nominatim: `https://nominatim.openstreetmap.org/reverse?format=json&lat=${lat}&lon=${lng}&zoom=18&addressdetails=1` with User-Agent header (required by Nominatim policy)
         - Parse response: extract address.suburb or address.neighbourhood or address.ward or display_name
         - Also call assignWard(lat,lng) to get wardId
         - Store in cache with expiry = Date.now() + 24*60*60*1000 (24h)
         - Return { wardId, displayName }
         - On error (network, 429, parse): log warning, return { wardId: assignWard(lat,lng), displayName: 'Unknown' }
       - `preloadDemoData(coords: [number,number][])`: Batch pre-geocode for demo dataset (run once at startup or via script)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Citizen Browser → Geolocation API | Browser requests user permission; user controls grant/deny |
| Citizen Browser → Supabase Storage | Direct upload with anon key; no backend involvement |
| Backend → Nominatim | External public API; rate-limited, no auth, cached |
| Backend → Local GeoJSON | File read at startup; trusted source (geohacker/india repo) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-12 | Information Disclosure | Browser geolocation | low | accept | User must grant permission; coordinates only used for complaint |
| T-01-13 | Tampering | Photo upload path | low | mitigate | Path includes timestamp+random; no user control over bucket structure |
| T-01-14 | Denial of Service | Supabase Storage upload | low | mitigate | 5MB limit; image/* only; Supabase free tier 5GB egress |
| T-01-15 | Denial of Service | Nominatim rate limit | high | mitigate | In-memory cache with 24h TTL; keyed by rounded coords; pre-geocode demo data |
| T-01-16 | Information Disclosure | Ward boundaries GeoJSON | low | accept | Public data from open source repo; no sensitive info |
| T-01-17 | Tampering | Ward assignment manipulation | low | mitigate | Runs server-side only; citizen cannot influence ward_id except via coordinates |
</threat_model>
