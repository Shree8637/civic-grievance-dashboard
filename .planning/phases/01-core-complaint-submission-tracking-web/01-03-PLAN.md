<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Supabase Storage | Direct photo upload (anon key) — separate from API |
| Browser → Nominatim (via backend) | Coordinates sent for reverse geocoding |
| API → Database | Ward assignment writes ward_id to complaint |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-11 | Tampering | Photo upload (Supabase) | low | mitigate | Bucket CORS restricted to allowed origins; file size/type validated client + server (via photoUrl URL format) |
| T-01-12 | Information Disclosure | Nominatim reverse geocode | low | accept | Only coordinates sent; no PII; public API |
| T-01-13 | Denial of Service | Nominatim rate limit (1 req/sec) | medium | mitigate | In-memory cache with 24h TTL keyed by rounded coordinates; pre-geocode demo data |
| T-01-14 | Tampering | Ward assignment | low | mitigate | turf.js booleanPointInPolygon handles edge cases; fallback to null if outside bounds |
| T-01-15 | Information Disclosure | Photo URL in tracking response | low | accept | Photo URL is public by design (Supabase public bucket); only accessible via tracking ID or phone lookup |
| T-01-16 | Spoofing | Geolocation API spoofing | low | accept | Browser Geolocation API can be spoofed; map pin alternative provides same capability; not a security boundary |
</threat_model>
